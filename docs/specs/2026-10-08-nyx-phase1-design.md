# NYX Phase 1 — core platform and repo split

Date: 2026-10-08. Status: approved in chat, pending written review.

## Goal

Split the project into two repositories:

- `TechnoVizor/NYX-project` — marketing site only (landing, legal, 404).
- `TechnoVizor/NYX` (new, public, Apache-2.0) — the platform: API plus the product UI (dashboard, login). This is what every "GitHub" link on the site points to.

Phase 1 delivers the core from the thesis brief (`NYX-project/all for this project/Bachelor_Cybersecurity_Platform_Final.md`, §50): monorepo, FastAPI backend, PostgreSQL, auth/RBAC, Docker Compose. Plugins, Temporal, graph, AI and the rest of the brief are later phases with their own specs.

Success:

1. `docker compose up` in `NYX` starts postgres, api, web; a fresh user can sign up on `/login`, land on `/app/dashboard`, reload and stay signed in, sign out.
2. Opening `/app/*` without a session redirects to `/login`.
3. CI is green: ruff + pytest against real Postgres; web lint + build.
4. `NYX-project` builds without the moved code; all its GitHub links go to `https://github.com/TechnoVizor/NYX`.
5. The `NYX` README reads as a person (NYX, first person) with the logo and the character, not just a tech sheet, and renders correctly in GitHub light and dark themes.

## 3. API (Phase 1)

Stack: Python 3.12, FastAPI, Pydantic v2 + pydantic-settings, SQLAlchemy 2 (sync, psycopg 3), Alembic, argon2-cffi, pytest, ruff, uv.

Endpoints:

| Method | Path | Behaviour |
|---|---|---|
| GET | `/healthz` | `{"status":"ok"}` and a `SELECT 1` against the database. |
| POST | `/api/v1/auth/signup` | `{email, password}`. Allowed when no users exist (that user becomes `admin`) or when `NYX_ALLOW_SIGNUP=true` (role `analyst`). Otherwise 403. Duplicate email 409. Password min 10 chars. Sets session cookie, returns user. |
| POST | `/api/v1/auth/login` | `{email, password}`. 401 with one generic message for unknown email or wrong password. Sets session cookie, returns user. |
| POST | `/api/v1/auth/logout` | Deletes the session row, clears the cookie. 204. |
| GET | `/api/v1/me` | Current user or 401. |

Data:

- `users`: `id uuid pk`, `email text unique` (lowercased before insert and lookup), `password_hash text`, `role text check in (admin, analyst, viewer)`, `created_at timestamptz`.
- `sessions`: `id uuid pk`, `user_id fk on delete cascade`, `token_hash bytea unique` (sha256 of the token), `created_at`, `expires_at`.

Sessions: 32-byte random token from `secrets.token_urlsafe`, only its sha256 stored. Cookie `nyx_session`, httpOnly, SameSite=Lax, `Secure` when `NYX_COOKIE_SECURE=true`, path `/`, max-age = `NYX_SESSION_TTL_HOURS` (default 168). Expired sessions are rejected on read (and deleted then).

RBAC: `role` column plus a `require_role(*roles)` dependency. Separate `roles` / `user_roles` tables are deferred until permissions need to be finer than three roles.

Config (env): `NYX_DATABASE_URL`, `NYX_ALLOW_SIGNUP` (default false), `NYX_COOKIE_SECURE` (default false), `NYX_SESSION_TTL_HOURS` (default 168).

Startup in Docker runs `alembic upgrade head` before `uvicorn`.

## 4. Web (product UI)

- Copied from `NYX-project/frontend` at commit `93650ae` (no history; the commit message names the source commit): `src/app/app/**`, `components/layout`, `components/shared`, the `components/ui` files they use, `lib/{api,types,mocks,nav,utils}`, `stores`, `providers`, `globals.css`, fonts setup from the root layout, icons.
- Login moves too: `(auth)/login` page, `login-view`, `auth-card`, `Grain`, the two login photos. The onboarding placeholder moves as well.
- URLs stay `/app/*` and `/login`, so links from the site keep working. `/` redirects to `/app/dashboard`.
- `next.config.ts` rewrites `/api/:path*` to `${API_URL}/api/:path*` (`API_URL=http://api:8000` in compose, `http://localhost:8000` in dev). The browser only talks to the web origin, so the cookie is first-party and no CORS is needed.
- Auth wiring:
  - `auth-card` posts to `/api/v1/auth/login` or `/signup`, shows the API error text inline, on success `router.push("/app/dashboard")`.
  - The Google button is removed (no OAuth in Phase 1).
  - `proxy.ts` in web: requests to `/app/*` without a `nyx_session` cookie redirect to `/login`. The real check is the API; the proxy only avoids flashing the dashboard.
  - Topbar shows the signed-in email from `/api/v1/me` and a sign-out action.
- Dashboard pages stay placeholders/mocks; wiring them to real data is a later phase.

## 6. Errors

- API returns `{"detail": "..."}` (FastAPI default) with 400/401/403/409/422; the login form shows `detail` (or the first validation message for 422).
- Network failure on login shows "I can't reach the server. Try again." and keeps the form filled.
- `/healthz` returns 503 if the database is unreachable, so compose healthchecks and CI see it.

## 7. Testing

- `api/tests`: pytest against real Postgres (`NYX_DATABASE_URL`, compose service locally, a `services: postgres` container in CI). Cases: first signup becomes admin; second signup 403 when disabled, 201 analyst when enabled; duplicate 409; login wrong password 401; `/me` with and without cookie; logout invalidates the session; expired session rejected; `require_role` blocks a viewer.
- `web`: `pnpm lint` + `pnpm build` in CI. Manual/Playwright check of login → dashboard → reload → logout against compose.
- `NYX-project`: `pnpm lint` + `pnpm build` after deletion.
- README: rendered check on GitHub in light and dark theme after push.
